# 데이터·개인정보 정책

## 원칙

- 출생 정보, 사주 결과, 라벨, 타로 질문, AI 해석 내용은 **애플리케이션에서 AES-256-GCM으로 암호화**해 `*_enc` 컬럼에 저장한다. 키(`DATA_ENCRYPTION_KEY`)는 Vercel 환경변수에만 있고 Supabase에는 없으므로, DB 관리자(Supabase 대시보드 포함)도 평문을 볼 수 없다.
- 사용자 데이터 테이블은 **Supabase RLS**로 본인 행만 접근할 수 있다. 서버는 사용자 요청마다 `authenticated` 역할 + JWT claim으로 쿼리해 RLS를 그대로 적용받는다 (`tests/rls.test.ts`가 실제 마이그레이션 SQL로 검증).
- 관리자 화면에는 집계와 오류 진단 정보만 나온다. 관리자 API에는 다른 사용자의 출생 정보·간지·질문·해석을 반환하는 경로가 없다.
- 로그(`usage_logs`)에는 사용자 ID 대신 HMAC 익명 ID, 토큰 수, 추정 비용, 처리 시간, 오류 코드만 남긴다.
- AI에는 확정 원국 등 해석에 필요한 최소 정보만 보낸다. 생년월일·출생 시각·출생지·이름은 보내지 않는다.
- 점봄 API에는 정규화된 양력 날짜·시각·성별이 전송된다 (제공자는 입력을 저장하지 않는다고 밝힘, 독립 확인 불가). 원치 않으면 `JEOMBOM_ENABLED=false`.
- 공유·이미지 저장에는 출생 정보를 넣지 않는다 (일주·요약 문장만).

## RLS 정책 요약

| 테이블 | authenticated | anon |
|---|---|---|
| `profiles` | 본인 행 읽기만 (쓰기 권한 없음 → 스스로 관리자 승격 불가) | 없음 |
| `saju_calculations` | 본인 행 읽기·쓰기·삭제 (활성 사용자만) | 없음 |
| `saju_engine_results` | 본인 행 + 본인 계산에만 연결 가능 | 없음 |
| `fortune_readings` | 본인 행 + 본인 계산에만 연결 가능 | 없음 |
| `invitations`, `usage_logs`, `admin_audit` | 없음 (서버 관리 연결만) | 없음 |

비활성화된 사용자는 `is_active_user()` 검사로 자기 기록도 읽을 수 없고, Supabase Auth에서 로그인도 차단(ban)된다.

## 테이블별 목적과 보존

| 테이블 | 목적 | 개인정보 | 보존 |
|---|---|---|---|
| `auth.users` (Supabase) | 계정 | 이메일, 비밀번호 해시(Supabase 관리) | 계정 삭제 시까지 |
| `profiles` | 표시 이름·권한·상태·대표 사주 | 표시 이름 | 계정 삭제 시 CASCADE |
| `invitations` | 초대 코드 (`SIGNUP_MODE=invite`일 때만 사용) | 코드 해시, 관리자 메모 | 미사용·만료/취소 후 30일 지나면 Cron이 삭제 |
| `saju_calculations` | 계산 입력·결과·검증 상태 | 입력·결과·라벨 암호화. 평문은 상태·사유·비식별 설정만 | 사용자 삭제 시까지 |
| `saju_engine_results` | 엔진별 결과·오류 | 결과 암호화. 평문은 엔진·버전·성공 여부·오류 코드·필드별 일치 여부(값 없음) | 계산 삭제 시 CASCADE |
| `fortune_readings` | AI 해석·타로·별자리 | 내용 암호화 | 사용자 삭제 시까지 |
| `usage_logs` | 호출량·비용·제한 | 익명 ID만 | `USAGE_LOG_RETENTION_DAYS`(기본 180일), Cron이 삭제 |
| `admin_audit` | 관리자 작업 기록 | 관리자 ID, 대상 ID | 1년, Cron이 삭제 |

## 삭제 범위

| 사용자 동작 | 삭제되는 것 | 남는 것 |
|---|---|---|
| 프로필에서 생년월일 변경 | 이전 내 사주 계산과 그 해석 (새 출생 정보로 다시 계산) | 익명 사용량 로그 |
| 사주 기록 삭제 | 해당 계산, 엔진 결과, 연결된 AI 해석·오늘의 운세, 대표 사주 지정 | 익명 사용량 로그 |
| 타로·별자리 기록 삭제 | 해당 기록 | 익명 사용량 로그 |
| 모든 기록 삭제 | 본인의 모든 계산·엔진 결과·해석 | 계정, 익명 사용량 로그 |
| 계정 삭제 | Supabase Auth 계정 → 프로필 이하 전체 CASCADE | 익명 사용량 로그, 초대 기록(사용자 연결은 NULL) |

**캐시**: 계산 결과 캐시는 DB(`saju_calculations.cache_key`)에만 있다. 서버 메모리 캐시가 없으므로 기록을 지우면 캐시도 함께 사라진다. 오늘의 운세·별자리의 "같은 날 재사용"도 저장된 해석 행 기준이라 삭제하면 사라진다.

**처리 범위 밖**: 점봄 API의 CDN 캐시(제공자 문서에 명시), Anthropic API 측 보존(Anthropic 정책), Supabase 백업(플랜별 보존 기간), 사용자가 직접 저장·공유한 이미지.

## 캐시 키

계산 캐시 키 = HMAC(사용자 ID + 정규화 입력 + 시간 보정·자시 설정 + 엔진 버전 + 판정 규칙 버전). 설정이나 엔진 버전이 다르면 캐시가 분리되고, 사용자 사이에는 공유하지 않는다.
